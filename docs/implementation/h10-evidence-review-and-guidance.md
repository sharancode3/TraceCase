## 1. Executive Summary & Operation

In accordance with **P2-06**, Person 2 has delivered the **Evidence Review Agent (AT-ROLE-003)**.

The agent consumes authoritative verification facts (locked verdict, assertion outcomes, baseline reset results, tested environment) and sanitized safe evidence references. It synthesizes a structured narrative explanation comparing Attempt 1 and Attempt 2, differentiating observed facts from diagnostic hypotheses.

### Core Architectural Invariants:
1. **Locked Verdict Immutability:** The deterministic `reproductionVerdict` generated by code verification is absolute and non-negotiable. The model cannot alter, upgrade, or dismiss the verdict under any circumstances.
2. **Observation vs Hypothesis Separation:** Explanations of potential root causes (such as row-index vs task-ID mismatch) are strictly tagged as hypotheses (`isVerifiedFact: false`). They are never presented as proven root causes.
3. **Reference Validation:** Evidence citations are deterministically validated against the set of verified safe artifact URLs supplied in the input. Any cited URL not in the eligible set is deterministically rejected and stripped.
4. **Deterministic Facts-Only Fallback:** If model inference times out, is skipped for budget, or errors out, the system automatically returns `EXPLANATION_UNAVAILABLE_FALLBACK` with 100% deterministic facts. Person 3 can always render the authoritative result without crashing or requiring a second model call.

## 4. Person 1 Integration Guidelines

1. **Invocation Timing:** Person 1 invokes `EvidenceReviewAgent.reviewEvidence(input)` during the `REPORT_DRAFTING` lifecycle phase, strictly AFTER deterministic verification has locked the verdict and all artifacts are indexed.
2. **Persistence:** Person 1 persists `output` in `investigations.report_json` and updates the investigation status to `COMPLETED`.
3. **Fallback Safety:** If the model call fails, Person 1 does NOT retry with a second model or fail the run; Person 1 stores the fallback output so core results remain 100% accessible.

## 5. Person 3 Integration Guidelines

1. **Results Display:**
   - Person 3 renders `output.executiveSummary` and `output.attempt1Comparison` in the investigation report view.
   - If `output.variant === 'EXPLANATION_UNAVAILABLE_FALLBACK'`, Person 3 renders the authoritative `deterministicFacts` badge and assertion scorecard directly.
2. **Hypothesis vs Fact Styling:**
   - Person 3 renders `output.diagnosticHypothesis` inside a clearly labelled "Unverified AI Hypothesis" box with a distinct amber badge, ensuring human engineers understand it is a suggestion rather than a verified fact.
3. **Evidence Links:**
   - Person 3 renders `output.evidenceCitations` as clickable links to safe artifact viewers.
